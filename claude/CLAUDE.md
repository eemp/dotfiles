# Global instructions

- Prefer small, focused changes; don't refactor unrelated code.
- Match the existing style and conventions of the repo you're in.
- Run the project's tests/linters after changes when they exist; report failures honestly.
- Use conventional commit messages (`feat:`, `fix:`, `chore:` …).
- When a requested change is the right size for a standalone PR, assume a PR is wanted, even if I don't say so: branch (off the default branch when the current one holds unrelated work), commit, push, open the PR, and give me its link. Don't stop at a local commit or a pushed branch.
- Never commit secrets, `.env` files, or credentials.
- Ask before force-pushing, or doing anything destructive.
