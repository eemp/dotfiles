# Global instructions

- Prefer small, focused changes; don't refactor unrelated code.
- Match the existing style and conventions of the repo you're in.
- Run the project's tests/linters after changes when they exist; report failures honestly.
- Use conventional commit messages (`feat:`, `fix:`, `chore:` …).
- Never commit secrets, `.env` files, or credentials.
- Ask before pushing, force-pushing, or doing anything destructive.
